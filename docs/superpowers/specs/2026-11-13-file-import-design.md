# 엑셀·CSV 받기 설계

작성 2026-11-13 · 상태: 검토 전

## 1. 왜 만드는가

PM-AI는 샘플 데이터로만 돌아간다. 실제 건물의 매달 숫자가 들어오는 길이 없다.
작은 건물은 엑셀로, 큰 건물은 ERP 내보내기 파일로 숫자를 갖고 있으므로, 파일을 그대로 올려 받는 길 하나로 둘 다 받는다.

**완료 기준:** 실제 건물의 한 달 지출 엑셀을 고치지 않고 올려서, 5분 안에 원장에 들어가고, 정산·이상치 검증이 그 숫자로 도는 상태.

## 2. 범위

| 넣는 것 | 빼는 것 |
|---|---|
| 지출 내역 받기 (1단계) | 고지서 발행, 월 마감, 전표 내보내기 (장부 기능) |
| 수납 내역 받기 (2단계, 같은 틀) | ERP와 직접 연결(API) |
| .xlsx, .csv | 옛 .xls 파일(엑셀에서 .xlsx로 다시 저장하라고 안내) |
| 가져오기 되돌리기 | 서버 저장(지금은 브라우저 저장 그대로) |

하면 안 되는 것: 확인 없이 바로 저장, 같은 파일 두 번 올렸을 때 중복 저장, 파일 내용을 외부 AI나 서버로 보내기.

## 3. 방식 비교

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 브라우저에서 읽기 (선택)** | 파일을 브라우저 안에서 읽고 규칙으로 열을 맞춘다 | PM-AI에 서버가 없어도 지금 바로 된다. 파일이 밖으로 나가지 않는다 |
| B. 서버에서 읽기 | pmai-mvp의 Python 코드를 서버로 붙인다 | 서버·로그인이 먼저 필요해 늦다. 서버가 생기면 A의 규칙을 그대로 옮긴다 |
| C. AI가 열을 맞추기 | 열 이름을 AI에 보내 추측시킨다 | 고객 장부가 외부로 나간다. 규칙으로 충분하고, 틀린 건 사람이 고르면 된다 |

## 4. 화면 흐름

회계 화면의 '지출 원장'(1단계)과 '수납·미수'(2단계) 탭에 **파일로 가져오기** 버튼을 둔다.

1. **파일 선택** — 끌어다 놓거나 고른다. 시트가 여러 개면 고르게 한다.
2. **열 맞추기** — 자동으로 맞춘 결과를 보여 주고, 틀린 열은 사람이 바꾼다. 처음 5줄을 함께 보여 준다.
3. **계정 맞추기** — 파일의 계정이 PMAI 관리비 항목 중 어디에 속하는지. 못 맞춘 계정만 사람이 고른다.
4. **미리보기** — 새로 들어갈 줄, 이미 있는 줄(건너뜀), 못 읽은 줄과 이유, 합계 금액.
5. **반영** — 확인을 눌러야 저장. 감사 로그에 남는다.

같은 건물에서 같은 양식을 다시 올리면 2·3번은 저장해 둔 대로 넘어가 4번부터 보인다.
회계 화면에 '가져온 기록' 목록을 두고, 묶음마다 **되돌리기**를 둔다.

## 5. 읽는 규칙

**파일**
- CSV: 직접 만든 읽기 함수. 따옴표·줄바꿈·쉼표 든 금액 처리. 글자 깨짐을 막기 위해 UTF-8로 읽어 보고 깨지면 EUC-KR(한글 엑셀 기본)로 다시 읽는다.
- XLSX: 읽기 전용 라이브러리 하나를 버튼을 누를 때만 불러온다(첫 화면 용량에 영향 없음). 라이브러리는 구현 계획에서 보안 권고를 확인해 고른다.
- 맨 위 제목 줄은 건너뛰고, 아는 열 이름이 가장 많이 나오는 줄을 열 이름 줄로 본다(위 20줄 안에서).

**열 맞추기** — 항목마다 후보 이름 목록(pmai-mvp 대응표를 가져와 넓힘). 공백·괄호·대소문자를 지우고 비교.

| 지출 항목 | 필수 | 후보 이름 예 |
|---|---|---|
| 금액 | ○ | 금액, 공급가액, 차변, 지출액, 출금 |
| 계정 | ○ | 계정, 계정과목, 계정코드, 항목, 비목 |
| 귀속월 |  | 귀속월, 회계월 (없으면 일자에서, 그것도 없으면 화면에서 고른 월) |
| 일자 |  | 일자, 전표일자, 거래일, 지급일 |
| 거래처 |  | 거래처, 거래처명, 업체, 지급처 |
| 적요 |  | 적요, 내역, 비고, 내용 |
| 부가세·증빙번호 |  | 부가세, 세액 / 증빙번호, 세금계산서번호 |

| 수납 항목(2단계) | 필수 | 후보 이름 예 |
|---|---|---|
| 호실 | ○ | 호실, 호수, 동호 |
| 고지액 | ○ | 고지액, 부과액, 청구액 |
| 수납액 | ○ | 수납액, 입금액, 납부액 |
| 임차인·납기·입금일·월 |  | 상호, 입주사 / 납기일 / 입금일, 수납일 |

**값**
- 금액: 쉼표, '원', 괄호 음수 `(1,000)`, 세모 음수 `△1,000` 처리. 대변 열이 있으면 차변 − 대변.
- 날짜: `2026-10-05`, `2026.10.05`, `20261005`, 엑셀 날짜 숫자.
- 합계·소계 줄, 금액 0인 줄은 건너뛰고 건너뛴 수를 보여 준다.

**중복 방지** — 줄마다 (건물, 월, 일자, 계정, 거래처, 금액, 적요, 증빙번호)로 지문을 만든다. 이미 있는 지문은 건너뛴다. 한 파일 안에서 똑같은 줄이 여러 번 나오면 순번을 붙여 모두 받는다.

**계정 → 관리비 항목** — ① 저장해 둔 대응 ② 항목의 계정 목록과 같은 이름·코드 ③ 사람이 고름. ③에서 고른 것은 건물별로 저장한다. 항목을 못 정한 줄은 반영하지 않는다(건너뜀으로 표시).

## 6. 코드 구조

| 파일 | 일 |
|---|---|
| `src/engine/importTable.ts` | CSV·XLSX → 표(줄×칸). 글자 깨짐 처리, 열 이름 줄 찾기 |
| `src/engine/importMap.ts` | 후보 이름 목록, 열 자동 맞추기, 금액·날짜 읽기 |
| `src/engine/importLedger.ts` | 표 → 지출 줄, 지문, 미리보기 계산 (순수 함수) |
| `src/engine/importReceivables.ts` | 2단계: 표 → 수납 줄 |
| `src/pages/accounting/ImportDialog.tsx` | 4장의 다섯 단계 화면 |
| `src/store/store.ts` | `importBatches`, `importProfiles`(건물별 열·계정 대응), `applyImport`, `undoImport` |
| `src/domain/types.ts` | `Expense`에 `batchId?`, `fingerprint?`, `date?`, `vat?`, `docNo?` 추가 |

기존 지출 줄에는 새 칸이 없어도 그대로 동작한다. 손으로 넣은 줄은 되돌리기 대상이 아니다.

## 7. 검증

- 단위 테스트: 제목 줄 있는 파일, EUC-KR 파일, 차변/대변 파일, 괄호 음수, 합계 줄, 같은 파일 두 번, 계정 못 맞춘 줄, 되돌리기.
- 샘플 파일: pmai-mvp의 전표 샘플과 직접 만든 '작은 건물 엑셀' 2종.
- 브라우저에서 올리기 → 미리보기 → 반영 → 정산 실행 → 이상치가 가져온 숫자로 나오는지 확인.

## 8. 알려진 한계와 남은 일

- **실제 건물 파일로 확인하지 못했다.** 후보 이름 목록은 가정이다. 실제 지출 엑셀 1~2개(금액은 가려도 됨)가 있어야 맞는지 안다. — 담당: 혁준 → 이사님, 구현 시작 전
- 브라우저 저장소 한도(약 5MB) 때문에 건물 하나의 몇 년치 정도만 담긴다. 서버가 붙으면 옮긴다.
- 수납 파일 양식은 건물마다 차이가 더 커서, 2단계는 실제 파일을 본 뒤 후보 이름을 정한다.

## 9. 구현자가 정할 것

XLSX 라이브러리 선택, 화면 세부 배치, 지문 해시 방식.

**정한 것(구현 중):** XLSX 라이브러리는 `read-excel-file` 9.3.12로 고정 — 읽기 전용, 2026-10-07 공개(14일 지남), 이 패키지로 늘어난 취약점 없음(`npm audit`의 기존 2건은 jspdf·dompurify 것). 첫 화면과 따로 묶여 버튼을 누를 때만 불러온다(47.6KB).
